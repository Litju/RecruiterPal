# RecruiterPal

**The agent-driven workspace for evidence-based recruiting.**

RecruiterPal turns recruiting from a fragmented queue of manual coordination tasks into a continuously observed, evidence-aware execution system. It exists to reduce **recruiter orchestration debt**: the daily burden of discovering what changed across many active jobs and candidates, what is blocked, which stakeholder owes an action, what evidence is missing, what is at risk, what can be safely automated, and what requires human judgment.

> RecruiterPal is an independent agent-driven recruiting workspace. The idea grew from broader recruiting analytics problems explored in earlier technical work, but RecruiterPal was designed and implemented from scratch with its own architecture, data model, synthetic demo data, and governance boundaries.

## What it is

- A recruiter workspace and execution/orchestration system built around the **Today** control surface.
- An evidence and **decision-readiness** system: versioned hiring protocols, structured evidence observations, deterministic readiness computation — never opaque candidate "fit" scores.
- An **agent-driven** interaction model: Pal is an ambient contextual layer with typed UI intents and human-in-the-loop approvals, not a chat bubble.

## What it is not

- Not a fully autonomous hiring decision-maker. Pal never hires, rejects, or alters approved selection protocols autonomously.
- Not a black-box candidate ranker or resume keyword scorer.
- Not a surveillance product.

## Architecture

| Layer | Choice |
| --- | --- |
| Product | Next.js (App Router) + React + TypeScript strict |
| Agent runtime | [Eve](https://eve.dev) behind `packages/agent-runtime` adapter boundary |
| Model provider | OpenCode Go (`https://opencode.ai/zen/go/v1`, OpenAI Responses-compatible), env `OPENCODE_GO_API_KEY` |
| Durable workflows | Vercel Workflow SDK |
| Canonical state | PostgreSQL / Neon via Drizzle ORM |
| Auth | Better Auth with organization-scoped RBAC |
| UI | Tailwind CSS, shadcn/ui-class primitives, Motion |

Core invariant: **deterministic code owns rules, permissions, calculations, mutations and authority; Vercel Workflow owns durable deterministic processes; Eve owns bounded agent reasoning; OpenCode Go provides the model; PostgreSQL owns truth; humans retain consequential hiring authority.**

## Getting started

Requirements: Node.js 24+, pnpm 10, Docker (or a local PostgreSQL) for integration tests.

```bash
pnpm install
cp .env.example .env.local          # fill in DATABASE_URL etc. (never commit it)
pnpm db:migrate                     # apply schema migrations
pnpm db:seed                        # generate the synthetic Northstar Labs demo world
pnpm dev                            # http://localhost:3000
```

Live Pal/model turns require `OPENCODE_GO_API_KEY`. Without it the product runs in a clearly labeled degraded mode: every deterministic surface works, agent turns fail closed with a truthful status.

## Quality gates

Pre-push runs format/lint/typecheck/unit tests/migration sanity/real-Postgres fast subset/secret scan/dependency audit/clean-room scan/production build. CI mirrors these plus Playwright golden flows and the Eve eval suite. See `docs/build-contract/13_TESTING_QA_PREPUSH_CICD.md`.

## Demo world

All committed data is **synthetic**, generated by owned deterministic seed generators: one fictional organization ("Northstar Labs"), fictional people, jobs, applications, scorecards, exceptions and messages designed to exercise the golden flows (competing-offer urgency, missing scorecards, scheduling capacity, requirement drift, decision-not-ready, cross-tenant isolation). No real candidate PII is ever committed.
